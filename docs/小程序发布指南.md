## 第 0 步：发布前必须知道的 3 件事

### 0.1 本项目是「自建账号」模式，审核员进不去必被驳回

小程序第一屏是登录页，需要邮箱 + 密码。微信审核员**不知道你的密码**，
点「提交审核」后如果填的账号无法登录，审核员看到的是一个登录框，
会直接判定「功能不完整 / 无法体验」并驳回。

**必须做的事**：在提审页面的「**测试账号**」和「**测试密码**」栏位，
填一个能正常登录的账号。这是微信官方为「需要登录」类小程序提供的标准入口。

准备两个账号（都填进提审备注更保险）：

| 用途 | 邮箱 | 密码 | 说明 |
|---|---|---|---|
| 审核账号 | `tong@chn.heart` | 你设置的密码 | 填在「测试账号」栏 |
| 备用账号 | 你自己的账号 | 你自己的密码 | 填在备注里备用 |

> ⚠️ **必须先确认账号密码确实可用**。
> 之前实测过：`.heart` 域名在 Supabase 的密码重置端点会触发邮件限流，
> 且控制台新建的用户**默认没有密码**。
> 请先在微信开发者工具里实际登录成功一次，再提审。

### 0.2 审核员会看到「空数据」

审核员用你的测试账号登录后，看到的是**你们自己的观影记录**。
这没问题，但要注意：

- 数据量要够看（太空白会显得功能不完整，建议至少有 10 条以上记录）
- 记录内容要正常（不要出现测试用的乱码、敏感内容）
- **绝对不要**在备注或数据里出现真实姓名、地址、身份证等个人信息

### 0.3 微信审核常见驳回原因对照

| 驳回原因 | 本项目是否会触发 | 应对 |
|---|---|---|
| 无法体验（进不去） | ⚠️ **会** | 填测试账号密码 |
| 功能未完整 | ⚠️ **会** | 确保测试账号有数据 |
| 类目不匹配 | ⚠️ **会** | 见第 2 步选对类目 |
| 未声明隐私收集 | ⚠️ **会** | 见第 3 步 |
| 涉及未开放接口 | ❌ 不会 | 本项目只用 `wx.request` / `wx.createInnerAudioContext` / `wx.setStorageSync` / `wx.shareFileMessage`，均为基础库开放能力 |
| 内容涉及版权（TMDB 海报） | ⚠️ 低风险 | 见第 5 步说明 |

## 第 1 步：确认主体与备案（后台配置）

登录 <https://mp.weixin.qq.com> → 左侧「**设置**」→「**基本设置**」→ 「**主体信息**」

### 1.1 主体类型

如果是**个人**主体：小程序类目受限，只能选「工具 - 效率」等少数类目，
且**不能开通微信支付**（本项目不需要支付，无影响）。

如果是**企业**主体：类目选择自由，审核通过率更高。

### 1.2 小程序备案（关键前置）

> 2023 年起，国内主体的小程序**必须先完成备案**，未备案无法提交审核。

路径：「设置」→「基本设置」→「**小程序备案**」

需要准备：
- 主体负责人身份证（个人）或营业执照（企业）
- 负责人手机号
- 负责人人脸核验（用微信扫码做活体检测）
- 网站/小程序的服务内容说明

> **备案通常需要 1 至 20 个工作日**，微信会给你发短信通知进度。
> 这是整个发布流程里**最耗时**的一环，建议今天就去提交。

备案通过后状态会显示「**已备案**」。

### 1.3 ✅ 完成标志
后台「基本设置」页显示主体信息完整，备案状态为「已备案」。

## 第 3 步：声明隐私保护指引（**最容易被忽略，但会直接卡审**）

路径：「设置」→「用户隐私保护指引」→「更新」

微信 2023 年 9 月起强制要求：只要小程序**收集用户信息**，
就必须填写《用户隐私保护指引》并在小程序内提供查看入口。

### 3.1 本项目实际收集的信息

只有**邮箱地址**（用户在登录页手动输入，用于账号登录），不涉及手机号、位置、相册。

### 3.2 填写建议

按微信后台的表单逐项填写：

| 表单项 | 填写内容 |
|---|---|
| 收集的用户信息类型 | 邮箱地址 |
| 收集场景 | 用户在登录页输入账号密码时收集 |
| 用途 | 用于账号登录与身份验证，识别是否为账号本人 |
| 存储方式 | 存储于开发者自有服务器（Supabase），境内 |
| 保存期限 | 账号存续期间 |
| 第三方共享 | 不共享 |
| 收集方式 | 用户主动输入 |

同时勾选「**邮箱地址**」的必填项。

### 3.3 小程序内的查看入口（后台会强制要求）

微信会检测到你声明了隐私收集项，但代码里**没有**调用隐私接口弹窗，
后台可能提示「未找到隐私协议展示入口」。

两种解法（任选其一）：

**方案 A（推荐，改动最小）**：在「设置」页面底部加一行文字链接，
点击后用 `wx.showModal` 展示隐私政策全文。文字内容要**完整覆盖**后台声明的每一项。

**方案 B（规范做法）**：调用官方隐私协议组件：

```js
// 在 app.js onLaunch 中
if (wx.requirePrivacyAuthorize) {
  wx.requirePrivacyAuthorize({
    onNeedPrivacyAuthorization: () => {
      wx.showModal({
        title: '隐私保护指引',
        content: '本小程序仅收集您的邮箱地址用于账号登录，不收集其他个人信息。',
        success: () => wx.openPrivacyContract({}),
      });
    },
  });
}
```

> 在你决定之前，**先按方案 A 走**——改一个字符串就行，风险最低。
> 需要我帮你加这段代码就说一声。

### 3.4 ✅ 完成标志
后台「用户隐私保护指引」状态为「**已生效**」，且小程序内可查看。

## 第 5 步：上传代码并提交审核

### 5.1 本地校验（先做，别浪费审核机会）

在微信开发者工具里：
1. 菜单「**工具**」→「**构建 npm**」→ 不需要，跳过
2. 确认控制台**无报错**
3. 用「**预览**」生成二维码，用自己手机扫码真机测试一遍：
   - 登录能进
   - 首页有数据
   - 点「观影记录」能跳转
   - 背景音乐能响
4. 右上角「**详情**」→「本地设置」→ 确认「**不校验合法域名**」在上传前是
   **关闭**状态（提交审核后线上环境必须走真实域名校验）

### 5.2 上传

微信开发者工具右上角「**上传**」→ 填写：
- **版本号**：`1.0.0`（只能数字和点，每次发布要递增）
- **项目备注**：
  ```
  情侣观影记录工具。首页展示观影统计与快捷入口，
  可查看已看电影、想看清单、成就徽章与统计图表，
  支持从豆瓣/TMDB 搜索添加电影，CSV 导入导出与 JSON 备份。
  ```

## 第 6 步：审核结果处理

### 6.1 通过

路径：「管理」→「版本管理」→「**发布**」→ 确认发布。

发布后小程序对所有用户可见。可在「版本管理」查看线上版本。

### 6.2 被驳回

驳回原因会附在审核意见里。按下表处理后**重新上传一个新版本号**：

| 驳回意见 | 处理动作 |
|---|---|
| 无法体验 / 功能不完整 | 检查测试账号密码是否有效；确认审核员看到的页面有内容 |
| 类目不符 | 回第 2 步改类目，或调整功能描述使其与「效率工具」相符 |
| 未声明隐私 | 回第 3 步补齐隐私保护指引与小程序内查看入口 |
| 涉嫌诱导分享 | 本项目无分享功能，若有此提示可忽略并申诉 |
| 涉及版权（海报） | 见下方说明 |

> **关于 TMDB 海报版权**：微信审核有时会质疑图片版权。
> 应对方式二选一：
> 1. 在审核备注中说明图片来源与用途（推荐，审核员通常认可）
> 2. 若被反复驳回，把海报替换为代码内置的占位图（`🎬` 已在用）

### 6.3 申诉

对驳回结论有异议时，在「版本管理 → 审核详情」点击「**申诉**」，
说明理由。申诉一般 1 至 3 个工作日。

## 第 7 步：发布后的运维

### 7.1 日常使用注意

- **改了代码必须重新上传 + 提交审核 + 发布**，线上不会自动更新
- 每次上传版本号要递增（1.0.0 → 1.0.1 → 1.1.0）

### 7.2 数据安全

- Supabase 的 `service_role` key **绝不能**写进代码或提交到仓库
- 小程序端只放 `anon` key（有 RLS 保护，公开是安全的）
- 定期在 Supabase 控制台检查 Authentication → Users，有陌生账号就删掉

### 7.3 备案与资质续期

- 小程序备案到期需重新备案
- 服务类目变更后需重新审核
