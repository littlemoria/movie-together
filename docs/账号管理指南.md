# 账号管理指南

> CineMemo 支持多账号登录，各账号共用同一份 Supabase 数据。
> 本文说明如何新增账号、排查登录失败，以及账号之间的权限模型。

---

## 一、权限模型（先理解这一条）

| 项 | 现状 |
|---|---|
| 数据隔离 | **无隔离**。`movies` / `settings` 表按 `authenticated` 角色放行，任何登录用户都能读写全部记录 |
| `settings` 存储 | 全局固定 key `eq.global`，所有账号共享同一份设置 |
| 网页版 `isAdmin` | 已等同于 `isAuthenticated`，**不代表管理员角色**，无邮箱白名单 |
| 公开注册 | 已关闭（`signup_disabled`），新账号只能在 Supabase 控制台创建 |
| 匿名访问 | 已关闭，anon 角色对业务表无任何权限（返回 HTTP 401） |

**结论**：新增账号不需要改任何代码。只要账号在 Supabase 里能正常登录，两端就自动可用且数据互通。

---

## 二、新增账号（推荐做法）

### 步骤 1：在 Supabase 控制台创建用户

1. 打开 <https://supabase.com/dashboard> → 选择项目 `zbghffgydxzufzfuozwq`
2. 左侧 **Authentication** → **Users** → 点 **Add user** → **Create new user**
3. 填写：
   - **Email**：如 `tong@chn.heart`
   - **Password**：设置一个密码（≥ 8 位）
   - 勾选 **Auto Confirm User**（关键！否则登录会报 `email_not_confirmed`）
4. 保存，记下生成的 **UID**

### 步骤 2：验证账号可用

用项目自带的诊断脚本（**只读，不写任何数据**）：

```bash
node scripts/check-account.js <邮箱> --proxy http://127.0.0.1:7890
```

输出示例：

```
✅ 公开注册已关闭（signup_disabled）——新账号只能在 Supabase 控制台创建
✅ 该账号存在（正在发送密码重置邮件，触发限流）
✅ RLS 已对匿名访问关闭（HTTP 401）——数据仅登录用户可见
```

带上密码可完整验证登录与数据可见性：

```bash
node scripts/check-account.js <邮箱> <密码> --proxy http://127.0.0.1:7890
```

### 步骤 3：确认登录成功后的 UID

登录成功时脚本会打印 UID。若与预期不符，会给出警告。

## 三、排查登录失败

### 3.1 先跑诊断脚本

```bash
node scripts/check-account.js <邮箱> <密码>
```

### 3.2 错误码对照表

| 错误码 | 含义 | 处理方式 |
|---|---|---|
| `invalid_credentials` | 密码错误 **或** 账号不存在 | GoTrue 出于防枚举统一返回此码，两者无法区分 |
| `email_not_confirmed` | 邮箱未验证 | 控制台勾选 **Auto Confirm User** |
| `email_address_invalid` | 邮箱域名不被 Supabase 接受 | 改用常见域名新建账号 |
| `signup_disabled` | 实例已关闭注册 | 属正常状态，用已有账号登录 |
| `over_email_send_rate_limit` | 邮件发送限流 | 说明账号存在，稍后再试 |

### 3.3 需要区分「密码错」还是「账号不存在」时

传入 **service_role key**（只读查询用户列表）：

```bash
node scripts/check-account.js <邮箱> --admin-key <service_role_key>
```

脚本会列出该邮箱的用户记录、UID、Email Confirmed 状态与最后登录时间。

> ⚠️ **service_role key 拥有完全的管理权限（可读写所有数据、可删除账号），切勿提交到代码仓库、勿粘贴到聊天窗口。**
> 获取路径：控制台 → Project Settings → API → service_role → Reveal。
> 本脚本只做 `GET /auth/v1/admin/users`，不会修改任何数据。

---

## 四、忘记密码怎么办

1. 优先在网页版或小程序用「忘记密码」流程（若邮箱域名被接受，会收到重置邮件）
2. 域名不被接受时，由管理员在控制台重置：
   **Authentication → Users → 选中用户 → ⋮ 菜单 → Reset password**

---

## 五、安全须知

| 项 | 说明 |
|---|---|
| anon key | 公开信息，**可以**入库；有 RLS 保护，未登录读不到任何数据 |
| service_role key | **绝不可入库**。若误提交，立即在控制台 Rotate 并清理 git 历史 |
| 真实密码 | 不要写进代码或提交到仓库。此前会话中已暴露过密码的账号应尽快修改 |
