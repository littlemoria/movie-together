# CineMemo 微信小程序接入方案

> 目标：在不破坏现有网页版、不影响两人私密使用的前提下，为 CineMemo 新增一个微信小程序客户端，与网页版共享同一套 Supabase 数据层，后续同步迭代、尽量降低重复开发与维护成本。

---

## 一、结论先行

- **数据层与业务规则 100% 复用**：网页版上一轮重构已经抽离出 `domain.js`（数据契约与纯业务规则）、`repository.js`（数据仓储，`transport` 可注入）、`store.js`（状态容器），这三层**不依赖 DOM / localStorage / fetch**，可直接迁移进小程序。
- **界面层必须重写**：网页版 `components.js` / `app.js` / `index.html` 是浏览器 DOM 绑定，无法复用，需用 WXML / WXSS / 页面 JS 重写。
- **登录沿用 Supabase 邮箱 + 密码**：零额外服务端，两人继续共用一个账号，数据天然互通。
- **两个受限功能做减法**：背景音乐（网易云外链）与本地文件上传背景图在小程序平台受限，首版不纳入。

---

## 二、可复用资产 vs 需重写清单

### 2.1 直接复用（迁移即用）

| 网页版文件 | 迁移到小程序后的角色 | 复用方式 |
|---|---|---|
| `js/domain.js` | `miniprogram/utils/domain.js` | **几乎原样复制**。纯函数，无平台依赖 |
| `js/repository.js` | `miniprogram/utils/repository.js` | 保留接口，**仅替换 `transport`**：把 `fetch` 换成 `wx.request` 适配器 |
| `js/store.js` | `miniprogram/utils/store.js` | 原样复制。UMD 包装在小程序里改为 CommonJS `module.exports` |

### 2.2 需要平台适配

| 网页版能力 | 小程序对应方案 | 说明 |
|---|---|---|
| `localStorage`（配置/想看/成就/备份） | `wx.setStorageSync` / `wx.getStorageSync` | 语义等价，键名保持一致便于日后对齐 |
| `IndexedDB`（离线缓存/同步队列） | `wx.setStorageSync`（数组） | 首版可先做**简化离线**：仅缓存最近一次数据，不做完整离线队列 |
| `fetch`（Supabase REST / TMDB） | `wx.request` | 包一层 `wxTransport(request)` 注入 `repository` |
| Service Worker（静态缓存/离线） | 小程序自带包缓存，无需 SW | 不迁移 |
| 背景音乐（网易云外链） | ❌ 首版不做 | 外链域名无法配为合法域名，`InnerAudioContext` 受限 |
| 本地文件上传背景图 | ❌ 首版不做 | 需 `wx.chooseMedia` + Supabase Storage，暂不启用 |

### 2.3 必须重写（界面层）

| 网页版模块 | 小程序页面 |
|---|---|
| 首页（观看次数/最近观看/添加按钮） | `pages/home/home` |
| 影单（已看/想看切换、搜索、筛选、增删改） | `pages/movies/movies` |
| 成就（徽章卡片/进度） | `pages/achievements/achievements` |
| 统计（累计/类型分布/月度趋势/日历） | `pages/stats/stats` |
| 设置（主题/背景/备份/登录） | `pages/settings/settings` |
| 登录（表单） | `pages/login/login` 或内嵌于设置页 |

## 三、数据互通架构

### 3.1 单一数据源（关键设计）

网页版与小程序**读写同一个 Supabase 项目、同一张 `movies` 表和 `settings` 表**，通过 Supabase Auth 的同一账号 + RLS 保证权限一致。因此：

- 网页版新增的记录，小程序打开即可见（反之亦然）。
- 无需同步桥、无需双写、无需数据迁移。

### 3.2 数据流

```
小程序页面 JS
   │  调用
   ▼
utils/store.js  ── 状态容器（单一数据源）
   │
   ▼
utils/api.js（薄封装，等同网页版 js/api.js 的角色）
   │
   ▼
utils/repository.js ── 数据仓储
   │   transport = wxTransport(request)
   ▼
wx.request ──> https://<project>.supabase.co/rest/v1/movies|settings
               （HTTPS + 合法域名白名单）
```

### 3.3 认证流

```
登录：wx.request → POST /auth/v1/token?grant_type=password
      返回 access_token / refresh_token
      → 存入 wx storage + 内存
数据请求：repository.request() 自动附加 Authorization: Bearer <access_token>
登出：POST /auth/v1/logout + 清除本地 token
```

> 说明：小程序不用 `wx.login`，因此**无需** code2Session、无需 OpenID 映射、无需 Edge Function。直接复用 Supabase 的 REST Auth 端点（`/auth/v1/token`），与网页版 `signInWithPassword` 走的是同一套账号体系。

### 3.4 会话保持

- access_token 默认 1 小时过期，用 refresh_token 在 `/auth/v1/token?grant_type=refresh_token` 续期。
- 小程序无 `localStorage`，token 存 `wx.setStorageSync`，启动时 `app.js` 恢复会话。

## 四、合法域名清单（发布前必配）

在小程序后台 **开发管理 → 开发设置 → 服务器域名** 中配置：

| 域名 | 用途 | request 合法域名 | 备注 |
|---|---|---|---|
| `https://zbghffgydxzufzfuozwq.supabase.co` | Supabase 数据 + Auth | ✅ 必配 | 你的项目域名 |
| `https://api.themoviedb.org` | TMDB 搜索/详情 | ✅ 必配（若用 TMDB） | 国内可达性不稳，见 §8 |
| `https://image.tmdb.org` | TMDB 海报 | 无需（走 `<image>`） | 图片不走 wx.request 白名单 |

> 注意：**小程序合法域名不支持 IP、不支持端口、必须 HTTPS 且已备案**。Supabase 的 `*.supabase.co` 满足要求。

## 五、页面清单与功能对齐

| 页面 | 首版功能 | 数据来源 | 复用 |
|---|---|---|---|
| 登录 | 邮箱 + 密码登录、登出、会话恢复 | Supabase Auth | repository Auth 端点 |
| 首页 | 观看次数、累计时长、最近 3 条、添加入口 | `movies` | `domain.getWatchedMovies` / `getTotalMinutes` |
| 影单 | 已看/想看切换、按月分组、搜索、按类型/年份/月份筛选、新增/编辑/删除 | `movies` + `settings.wishlist` | `domain.normalizeMovie` / `mergeMovies` |
| 成就 | 徽章列表、已解锁状态、进度条 | 本地计算 + `settings.unlockedAchievements` | 网页版成就规则 |
| 统计 | 累计、类型分布、月度趋势、观影日历 | `movies` | `domain.getGenreStats` / `getMonthlyStats` |
| 设置 | 主题、背景色/透明度、自动备份开关、登录状态 | `settings` | `domain.normalizeSettings` |

## 七、平台差异与限制（需提前知情）

| 差异点 | 影响 | 应对 |
|---|---|---|
| **TMDB 国内可达性** | 搜索/海报可能加载慢或失败 | 首版保留手动输入电影名+时长，TMDB 作为可选增强；海报失败显示占位图 |
| **背景音乐** | 无法配置网易云外链为合法域名 | 首版移除，后续若需要可上传音频到 Supabase Storage 再配域名 |
| **本地文件上传背景图** | 无 `input[type=file]` | 首版移除；后续用 `wx.chooseMedia` + Supabase Storage |
| **订阅消息** | 小程序推送需「订阅消息」，普通场景一次订阅发一条 | 双人「对方新增记录提醒」首版不做，后续用订阅消息 + Edge Function |
| **审核门槛** | 个人主体可用，但功能需合规（无诱导分享、无支付等） | 本工具纯私用工具，风险低 |
| **Canvas 图表** | 网页版用 Canvas 2D 自绘，小程序用 `<canvas type="2d">` 或 WXSS 条形图 | 统计页图表需重写，可用 ECharts 小程序版或轻量自绘 |

## 九、当前阻断与依赖

**阻断项**：WorkBuddy 内置小程序脚手架工具返回 `template_unavailable: 模板文件哈希不匹配 app.js`。经诊断，模板资产目录 `.../templates/native-basic/1.0.0/` 内所有文件的实际 `sha256` 与 `manifest.json` 记录均不匹配（例如 `app.js` 实际 `31bafc6b...` vs 记录 `9b623119...`），属插件模板资产缺陷，非项目问题。

**解除方式**（三选一）：
1. 等 WorkBuddy 修复模板资产后重新脚手架（推荐，符合规范）；
2. 用户授权后，按模板文件结构手工创建等价工程（可立即推进，但偏离脚手架规范）；
3. 上报该工具缺陷，等待官方处理。

## 十、与网页版的长期维护约定

1. **数据契约以 `domain.js` 为准**：任何字段新增/变更，两版共用同一份契约文件（未来可考虑抽到独立目录双向引用）。
2. **接口约定统一**：`repository` 的返回结构 `{ data, error }` 与错误码（`AUTH_REQUIRED` / `NETWORK_ERROR` / `PERMISSION_DENIED` 等）两版一致。
3. **同步规则统一**：`SYNC_POLICY`（云端权威 + last-write-wins）常量两版共享。
4. **不重复造轮子**：业务规则（统计、成就、合并）只写一份，两版都从 `domain.js` 引用。
